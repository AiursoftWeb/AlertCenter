# 排班模块重构任务书（On-call Flexible Scheduling）

本文是已与产品负责人逐条确认的方案。范围内的接口、数据库、架构改动均已批准，实施时无需再等待确认。

## 背景

现有排班把每周固定切成 21 个 8 小时格子（`AnchorUtc` 起算），规则只能 8 小时，生成器按休息时长推算人数并用二分图匹配；校验器、保存（`HasValidSlots` 要求 21 格）、`_PreviewGantt.cshtml`、`_ScheduleEditor.cshtml`、`wwwroot/scripts/oncall-schedule.js`、`OnCallController` 都写死了 21×8h。值班是"承担事故响应责任"，不是连续工作，原来的休息限制不应阻止排班。

典型需求：北京时间，周一 22:00→周五 22:00、周五 22:00→下周一 22:00 两种班段，A、B、C 共用一个队列轮换：A、B、C、A……

## 目标

排班完全自由；检查只提醒不拦截；系统自动轮换并保证告警总能送到人；成员能看到自己的值班表，所有人能醒目看到当前值班负责人。

## 一、排班模型

1. `OnCallShift` 是自由时间段：任意 `StartsAtUtc` / `EndsAtUtc`（长度不限，分钟精度），0..n 名成员。去掉 8 小时、21 格、必须对齐 `AnchorUtc` 等全部限制。
2. 前端按团队 `TimeZoneId` 输入/显示本地时间，后端用 `TimeZoneInfo` 换算 UTC（正确处理夏令时）。
3. 每个班段记录来源：`Generated`（模板自动生成）或 `Manual`（手工新建，或生成后被手工改过）。
4. 现有数据原样保留（迁移后视为 `Manual` 或 `Generated` 均可，但不得改动其时间与成员）。
5. 原 `RestHours` / `MinimumStaff` 等"拦截型"字段改为提醒阈值（见第三节），可迁移到团队设置；不再参与保存校验。
6. SQLite 与 MySQL 两套迁移都要生成（按各自 `HOW_TO_ADD_MIGRATIONS.md`）。

## 二、生成模板（原"规则" `OnCallRule`）

1. 模板只用于批量填充，生成结果可随意再编辑。
2. 切分方式二选一：
   - 固定时长：每 N 小时一段（N 任意正数小时/分钟），从某个对齐点开始。
   - 每周交接点：团队时区下的"星期几 + 时刻"列表，如 `[周一 22:00, 周五 22:00]`，相邻交接点之间为一段（班段长度可以不同）。
3. 每段人数（默认 1）。
4. 轮换队列：团队成员按 `RotationOrder` 组成队列；每段取下一组人，队尾循环到队首。
5. 轮换策略（下拉）：
   - 纯队列：第 k 段取队列第 `(起点 + k) mod N` 人（每段多人时依次取连续的人）。
   - 偶数人数隔轮对调：当 N 为偶数且 N ≥ 4 时，每隔一轮将队列相邻两人对调（`A B C D | B A D C | A B C D …`），使每人在工作日班/周末班间交替且不会连值两段；N 为奇数或 N = 2 时退化为纯队列。
6. 手动生成：管理员选择时间范围生成；若覆盖已有班段，先展示将被替换的内容并确认后写入。
7. 自动续排：模板绑定团队并开启"自动续排"后，后台定时任务保证未来 4 周都有排班。只在最后一个已有班段之后追加，**绝不修改或删除已有班段**（包括手工改过的）。轮换从最后一个已排班段的值班人在队列中的下一位接着排；若该人已不在队列，则从队首开始。
8. 原 8 小时三班保留为一个模板预设（固定时长 8 小时、按原行为生成，但不再有拦截）。

## 三、检查：四类无效数据拦截，其余只提醒

保存时**只拦截**以下四类数据无效情况：
- 结束时间 ≤ 开始时间；
- 值班人不是团队成员或用户不存在；
- 同一团队同一人的班段严格重叠（两个无人班段也视为同一行，禁止重叠）；前一班结束时间等于后一班开始时间不算重叠；
- 并发版本冲突（沿用 `ScheduleVersion`）。

同人重叠校验覆盖手工保存、复制、模板生成、清空后重新生成及自动续排，并检查范围外保留班段；错误须本地化并标明人员与两个班段的时间。现存重叠数据仍可加载，预览保留全部班段和诊断，允许管理员修正后保存，不自动裁剪或丢弃冲突数据。

以下全部只产生提醒，照常保存：
- 时间空档（无人覆盖）；
- 同一团队不同人的班段重叠，或同一人跨团队撞班；
- 班段无人；
- 同一人休息时间不足阈值（跨团队也算）；
- 同一人连续值班超过阈值；
- 人数低于阈值；
- 已离开团队的成员仍挂在未来班段上（成员离队时其班段保留，不自动顶替）。

阈值放在团队设置（可空，空表示不检查该项）：最短休息小时、最长连续值班小时、每段最少人数。

提醒展示位置：编辑时实时显示；团队详情页与首页持续显示"未来 7 天排班问题"。

## 四、告警送达

1. `OnCallOceService`：多个班段同时覆盖某时刻时，合并所有成员为当前值班人（去重），不再报"重叠"错误。现有"原始收件人快照"逻辑保持不变。
2. 兜底接收人：团队新增"兜底接收人"（可选若干系统用户）。某时刻无人值班（无班段或班段无人）时，新事故邮件发给兜底接收人，并在投递记录中注明是兜底；仍未配置兜底时沿用现有"可见失败"。
3. 交接通知：每到班段交接时刻，若新班段中有上一时刻不在班的人，给这些新值班人发一封"未处理事故汇总"邮件，列出该团队绑定应用中尚未解决（未 resolved）的事故（严重级别、标题、状态、是否已 ACK、负责人、链接）。无未处理事故时不发。事故负责人不变。必须去重（同一班段同一人只发一次），走现有邮件投递与投递记录机制，进程重启或任务重跑不重复发送。
4. 主备值班、升级、班前提醒本期不做。

## 五、排班编辑界面

1. 仍按周翻页（周起点按团队设置，默认团队时区周一 00:00），可显示跨周班段，也可选择自定义范围。
2. 甘特图作为主要编辑界面，每个成员一行；另设无人班次行和交接点行。班次主体拖动可改变人员或时间，拖至另一已分配班次可交换值班成员，左右边缘拖动可调整开始或结束，交接点拖动同时调整两侧相邻班次；成员行空白处拖动可新建班次。默认按 30 分钟对齐，按住 Alt 精确到分钟；触屏先长按再拖动，可通过时间轴或图表背景横向滚动。
3. “精确编辑 / 批量操作”默认折叠，保留表格增删改、选中班次移动至指定人员和时间、两名在队成员整周交换，以及复制/生成到时间范围。在队成员姓名栏另设“交换整周”按钮，可拖至另一成员，或先选择按钮再选择目标成员行，交换显示范围内的排班。原生弹窗提供精确起止时间和 0..n 人选择；无论是否折叠工具，撤销、重做、重置、保存均保持可用。
4. 复制将当前草稿重复填入目标范围并裁剪至边界，目标可完整替换当前范围或某个已有复制范围，但不能与其部分重叠。复制和模板生成只修改草稿；覆盖已有班段时先展示替换清单并确认替换草稿，相交班段整体替换。所有修改（含复制范围）仅点击保存后写入，统一参与撤销、重做和重置；未保存内容不影响通知接收人。本节的草稿确认流程取代第二节手动生成的直接写入描述。
5. 键盘聚焦班次后：左/右方向键调整时间，上/下调整人员；Shift + 左/右调整结束时间，Shift + 上/下调整开始时间；Enter 打开弹窗，Delete 删除，Escape 取消。精确编辑控件提供不依赖拖动的操作路径。
6. 实时标出空档、重叠、无人、休息不足、连续值班过长、低于人数阈值和未来离队成员等提醒，不阻止保存。每人值班时长只统计当前显示范围，合并重叠部分；相邻周及其他团队保持只读，不计入当前范围的统计。
7. 编辑权限不变：`CanManageOnCall`；所有登录用户可查看，只读用户不显示编辑工具或编辑操作说明。离队成员不能新增或复制，修改其原班次时间前须先移除离队成员。
8. 中英文本地化跟随项目现有方式；时间按团队时区输入，夏令时不存在的时间无效，重复时间采用标准时间。

## 六、我的值班（`/OnCall/Mine`）

1. 入口：导航栏 Features 组新增"我的值班"；首页在"我的事故"卡片旁增加同风格卡片。
2. 顶部状态：正在值班时显示团队、结束时间与剩余时长；未值班时显示下一次值班开始时间与倒计时。
3. 未来班段：我在所有团队的未来班段，默认未来 8 周，按时间排序；每段显示团队、开始/结束、时长、同班其他人。
4. 历史班段：分页查看。
5. 统计：近 30 天与未来 4 周我的值班总时长。
6. 与我相关的提醒：跨团队撞班、休息不足等。
7. 时间同时显示团队时区与浏览器本地时间；两者相同时只显示一次。

## 七、当前值班负责人展示

1. 首页顶部"当前值班"横条，每个团队一行：团队名 · 当前值班人（姓名 + mailto 链接）· 本班结束时间 · 下一班值班人。无人值班的团队标红，并显示"告警将发给兜底接收人"（或未配置兜底的警示）。我自己在值班的那一行高亮。显示系统中所有团队。
2. 导航栏：当前用户正在值班时显示"值班中"小标记，点击进入"我的值班"。
3. 团队详情页顶部显示同样的当前值班人与下一班信息。
4. 当前值班人必须与告警通知使用同一套查询逻辑（`OnCallOceService`），保证页面与实际收件人一致。

## 八、iCal 订阅

1. 每个用户在"我的值班"页可生成/重置一个私密订阅链接（随机令牌，数据库只存哈希或足够安全的形式；重置后旧链接立即失效）。
2. 匿名可访问的 `.ics` 端点，凭令牌返回该用户的班段：过去 30 天 + 未来 12 周。
3. 每个班段一个 `VEVENT`：`UID` 用班段 Id（多团队/多成员下保证稳定唯一），`DTSTART`/`DTEND` 用 UTC，`SUMMARY` 含团队名，`DESCRIPTION` 含同班成员与站点链接；正确转义与折行（RFC 5545）。
4. 页面给出一键复制链接和"如何添加到手机/Outlook 日历"的简短说明。
